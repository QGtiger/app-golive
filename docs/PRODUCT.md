# GoLive 产品文档

版本：v0.1 草案 · 2026-09-07  
状态：供产品评审；本文描述目标行为，不代表功能已经完成。

## 1. 产品定位

GoLive 是一个把本地 Web 页面快速发布到线上、并获得访问地址的轻量桌面工具。

用户把项目或页面拖进来，必要时执行构建，点击发布，拿到可以打开、复制和分享的网址。首次配置之后，同一个项目再次发布只需一次点击。

主要用户是自己在本地写项目、经常需要临时预览或分享页面的开发者。

**核心流程：选择内容 → 执行可选脚本 → 上传 → 获取访问地址。**

## 2. 已确认的方向

- 第一版实现桌面客户端，使用 electron-vite，项目采用 monorepo。
- 支持源码项目，以及已经构建好的文件夹、单个 HTML。
- 支持用户配置发布前执行的脚本。
- 客户端参考现有网关接口契约，自行实现发布流程，不依赖原 CLI 的命令实现。
- 后续可能增加 Web 端。Web 端只接收已构建的内容，本轮不实现。
- 采用此前概念图的小窗口：日常发布、发布配置、发布成功。

## 3. 第一版范围

| 包含 | 暂不包含 |
| --- | --- |
| 拖入或选择本地项目、文件夹、HTML | Git 仓库拉取、云端构建 |
| 自动建议项目名、构建命令和上传目录 | 服务器管理、SSH、容器编排 |
| 可编辑的发布前脚本 | 后端服务部署、数据库管理 |
| 文件上传、发布登记、访问地址 | 团队、权限、计费、监控面板 |
| 项目配置记忆和少量最近项目 | 完整项目管理后台 |
| 发布阶段、日志、失败提示 | 版本历史页面、回滚、删除应用 |
| 全局连接设置 | DNS 配置、证书申请、自定义域名托管 |

源码项目也必须最终产出可上传的静态 Web 文件。第一版不会把 Node.js 后端程序部署成在线服务。

## 4. 三种输入，一套配置

| 输入 | 自动建议 | 发布行为 |
| --- | --- | --- |
| 含 `package.json` 和 build script 的项目目录 | 项目名、包管理器构建命令、`dist` 目录 | 执行脚本后上传产物 |
| 已构建目录，如 `dist/` | 脚本留空，上传整个所选目录，入口 `index.html` | 直接上传 |
| 单个 `.html` / `.htm` 文件 | 脚本留空，上传所选文件 | 以 `index.html` 作为上传入口 |

自动识别只提供建议，用户可以修改，不需要切换“项目类型”开关。

补充行为：

- 没有 build script 的目录默认直接上传，用户仍可填写脚本。
- 单个 HTML 内嵌 CSS、JS，或引用远程资源时可以独立发布。
- HTML 引用同目录的本地 CSS、JS、图片时，应选择完整文件夹，避免遗漏资源；识别到明显的本地依赖时提示改选文件夹。
- 不承诺静态分析能找到 JavaScript 动态生成的所有资源引用。
- 文件夹入口不是 `index.html` 时，用户可以指定其他 HTML，包括子目录入口。

## 5. 页面与交互

### 5.1 日常发布

一个主窗口，不设侧边栏。

从上到下：

1. 标题 `GoLive`，右上角设置入口。
2. 拖入区：`拖入项目、文件夹或 HTML`，提供选择文件夹和选择 HTML 的入口。
3. 已选内容卡片：应用名、本地路径。
4. 配置摘要：发布前脚本、上传内容；脚本为空显示 `直接上传`。
5. 可折叠的 `发布配置`。
6. 主按钮 `一键发布`。

未选择内容时主按钮不可用。未完成全局连接配置时，点击发布引导进入设置，不先执行脚本。

建议在空状态下展示最多 5 个最近项目，点击即可恢复配置；最近项目是本机便捷入口，不扩展成项目管理页面。

### 5.2 发布配置

| 字段 | 默认/示例 | 规则 |
| --- | --- | --- |
| 应用名称 | `my-web-app` | 对应服务端 `id`；自动建议、可编辑 |
| 发布前脚本 | `pnpm run build` | 可选、多行；为空直接上传 |
| 执行目录 | 所选项目目录 | 脚本工作目录，也是相对上传路径的基准 |
| 上传内容 | `dist`、`.` 或 HTML 路径 | 可以是文件夹或单个 HTML |
| 入口文件 | `index.html` | 文件夹模式可编辑；单文件模式自动确定 |
| 访问域名 | `my-web-app.lightfish.top` | 新应用使用；已有应用沿用服务端域名 |
| 发布备注 | 空 | 可选，不挤占日常界面 |

配置保存在客户端本机，按来源路径记忆，不向用户项目目录写入配置文件。

“发布前脚本”已经包含构建需求，不再设置一套独立的“构建脚本”字段。例如：

```sh
pnpm run generate
pnpm run build
```

按顺序执行；任一步失败，终止后续步骤与上传。不会默认自动安装依赖；需要安装时用户自行把命令写进脚本。

修改应用名称意味着发布到另一个服务端应用标识，不是重命名原应用。界面在字段旁说明这一点。

### 5.3 发布中

主窗口展示当前项目和阶段：

- 准备发布：检查配置、查询现有应用。
- 执行脚本：仅有脚本时显示。
- 上传文件：显示已完成文件数/总数。
- 登记发布：请求网关切换到新版本。

日志默认折叠，失败时自动展开，内容允许复制。构建阶段没有可靠百分比时显示进行中，不生成虚假的进度数字。

发布期间锁定项目选择与配置，防止正在执行的内容发生变化。第一版一次只运行一个发布任务。

脚本和上传阶段允许取消；登记发布开始后显示“正在确认发布结果”，暂不允许取消，避免把服务端可能已经成功的请求显示成已撤销。

### 5.4 发布成功

- 成功状态、应用名称。
- 实际访问地址。
- 主按钮 `复制链接`，次按钮 `打开网站`。
- `再次发布`：复用当前配置执行一次新发布。
- `更换项目`：返回选择入口。

成功的含义是文件上传完成、服务端接受发布登记。不能因此宣称 DNS、HTTPS 和页面内所有业务请求都已通过测试。

### 5.5 失败和不确定状态

| 情况 | 用户看到的结果 |
| --- | --- |
| 脚本退出码非零 | 执行失败、退出码和日志，不继续上传 |
| 产物不存在、入口错误 | 指出具体路径，引导修改上传内容/入口 |
| 部分文件上传失败 | 发布失败，不登记新版本；保留重试入口 |
| 服务端明确拒绝发布 | 展示接口错误，保留项目配置 |
| 发布请求超时/断网 | 查询服务端核对版本；仍不能确认时显示“结果待确认”，不直接重发 |
| 应用已停用或缺少可用域名 | 明确提示服务端配置问题，不展示误导性的成功网址 |
| 用户取消 | 显示“已取消”；已上传的临时版本文件可能保留，不声称远端已清理 |

## 6. 全局设置

首次使用配置一次，之后复用。

| 设置 | 用途 |
| --- | --- |
| 网关 API 基础地址 | 请求 `/routers/app/get`、`/routers/app/deploy` |
| OSS Region / Bucket | 上传目标 |
| OSS AccessKey ID / Secret | 桌面端直传凭据 |
| OSS/CDN 公共访问根地址 | 生成上传资源与入口 URL |
| 默认域名后缀 | 为新项目建议访问域名，默认 `lightfish.top` |
| 访问协议 | 默认 HTTPS；本地/测试环境可选 HTTP |

网关 Token 仅在实际部署存在鉴权要求时补充。已检查的 controller 没有定义 Token 字段，本轮不凭空建立登录流程。

凭据保存在操作系统安全存储中，设置页不回显已保存的 Secret。已有服务负责 DNS、证书和网关路由，填写域名不会自动创建这些基础设施。

## 7. 关键产品规则

1. 不自动执行拖入项目的脚本；用户点击“一键发布”后才执行。
2. 构建和上传过程不改写用户原始页面；资源处理在待上传副本上完成。
3. 新应用使用填写的域名；已有应用重新发布不会隐式变更域名。
4. 脚本留空就是直接上传，不要求 `package.json`。
5. 默认排除隐藏文件、环境文件和 `node_modules`，不跟随符号链接。
6. 每次发布生成独立版本目录；只有完整上传后才登记新版本。
7. 第一版不做自动回滚、自动重发发布请求或远程文件清理。

## 8. 验收清单

- [ ] 一个有 build script 的项目能构建、上传、登记并复制访问地址。
- [ ] 一个 `dist/` 目录无需源码即可发布，页面资源能从上传地址加载。
- [ ] 一个自包含 HTML 可以直接发布。
- [ ] 带本地资源依赖的 HTML 提示选择完整目录。
- [ ] 用户可改脚本、工作目录、上传目录和入口，并在重启后恢复。
- [ ] 脚本失败和部分上传失败都不会调用发布登记。
- [ ] 再次发布沿用同一个应用，产生新的版本。
- [ ] 已有域名以服务端返回为准，不误显示本地拟定的新域名。
- [ ] 可取消构建/上传，退出后没有遗留脚本进程。
- [ ] 凭据不出现在渲染进程返回值、明文配置或发布日志中。
- [ ] 无真实连接配置时，明确提示未配置，不用模拟成功代替真实发布。

## 9. 本轮建议，供检查

以下是实施默认方案，还没有经过你的逐项确认；可以在继续编码前调整：

- UI 使用 React + TypeScript，优先完成 macOS 开发与验证。
- 配置保存在客户端本机，不写入项目仓库。
- 桌面端直接上传 OSS，复用现有网关发布接口。
- 发布前脚本承担构建与准备工作，不再拆分多套脚本字段。
- 第一版只提供按域名访问的常用配置，不提供路由 path、config JSON 编辑器。
- 最近项目只做一个小列表；历史版本和回滚暂不做。

技术结构、接口字段及资源地址处理见 [技术方案](./TECHNICAL.md)。
